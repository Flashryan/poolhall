# 11 — As-Built Scaffold (for the design pass)

**Audience:** the Claude session doing visual/design work ("fill the
gap"). This is the exact inventory of what exists in the repo and on
local/staging as of 12 June 2026, who owns each piece, and where the
design gaps are. Build decisions still live in the numbered docs —
`10-ELEMENTOR-DESIGN-SYSTEM.md` is the visual contract; this document
maps that contract onto what has actually been built.

**The one rule that protects your work (read first):** every page and
template below is generated by an idempotent script in
`plugins/poolhall-integration/scripts/dev/`. Re-running a script (or
wp-admin → Poolhall Jobs → **Site setup**) **replaces that page's
Elementor document** (a timestamped backup goes to a
`poolhall_tpl_backup_*` option first — hard rule 11). So design changes
must round-trip: **edit the builder script, re-run it, verify** — do not
hand-edit a generated page in the Elementor editor/Novamira and stop
there, or the next setup run erases it. If a page must become
hand-owned, remove its step from `src/Admin/HealthPage.php` first and
say so in the README.

## 5. Dynamic seams the design must keep intact

**Shortcodes (server-rendered; the future Elementor widgets wrap the
same renderers — restyle via the ph-* classes, don't fork the markup):**

| Shortcode | Renders | Where |
|---|---|---|
| `[poolhall_job_search]` (+`variant="wide"`) | §11 search panel, GET → /jobs/ | home hero, jobs archive |
| `[poolhall_live_roles]` | live-count trust item (empty when 0 jobs) | home hero |
| `[poolhall_enquiry_form kind="hiring\|contact"]` | enquiry card + notices | employers, contact |
| `[poolhall_audience_switch]` | animated Candidates/Employers control | header |
| `[poolhall_account_link]` | Sign in / My account | header |
| `[poolhall_candidate_auth]` | all portal auth forms | /candidate/* |
| `[poolhall_style_guide]` | living style guide | /style-guide/ |

**Elementor query IDs (registered in the plugin — never re-point):**
`poolhall_jobs_archive` (ArchiveQuery: published, unexpired, + q/
location/sector GET filters, noindex when filtered) ·
`poolhall_featured_jobs` (FeaturedQuery: unexpired, `is_featured` meta
first then newest, max 6).

**Dynamic tags used in loop items / single job:** post-title, post-url,
post-terms (`poolhall_sector`), post-custom-field on the job meta keys
(`location_display`, `salary_display`, `job_reference`). Full meta list:
`Jobs/JobPostType::META_KEYS`.

**Form endpoints:** all forms POST to admin-post with nonce + honeypot +
`poolhall_human_check` filter (Turnstile attaches there later). Keep the
hidden fields and `id="enquiry"` anchors when restyling.

## 6. Design-system surface (where to change what)

| To change… | Edit… |
|---|---|
| Color/type/space/radius/shadow tokens | `shared.css` `:root` (`--ph-*`) — then re-run `configure-elementor-kit.php` so kit Globals stay synced |
| A reusable class (cards, badges, buttons, forms, hero, search, switch…) | `shared.css` registry section — bump `POOLHALL_CHILD_VERSION` in `functions.php` |
| A page's composition/sections | its `scripts/dev/create-*.php` builder, then re-run it (backup is automatic) |
| Loop card / single-job anatomy | `create-jobs-templates.php` |
| Header/footer anatomy | `create-theme-shell.php` |
| Anything the style guide shows | it re-renders live from the same contract — use /style-guide/ to verify |

Known wrapper quirk: classes set via a widget's Advanced tab land on the
**widget wrapper**, so element-level rules need descendant selectors —
`ph-h1…h4` already do this (`.ph-h3, .ph-h3 .elementor-heading-title`).
The parent-theme reset sizes raw h1–h6; never rely on bare headings.

   API key; design can prepare the section using `ph-card--review`

7. **Candidate portal visual pass** — portal pages are functional,
   design-system-classed server renders; doc 08 + doc 10 §19 describe
   the portal card/dashboard look. Restyle via classes around the

8. **Empty/edge states everywhere** — empty carousel (staging today!),

9. **Blog** — doc 01 §11: archive + 4 posts migrate from Wix; templates

**Unconfirmed-content guardrails (do not invent):** BJA price,

rule 7 — no `#` links), client names in schema. List: doc 05 §4.

## 8. Verification loop for any design change

```
edit script/css → re-run script (wp eval-file … or Site setup button)
→ hard-refresh frontend (child CSS is version-busted via functions.php)
→ check /style-guide/ if tokens/classes changed
→ composer lint && composer test   (plugin dir; 125 unit tests)
→ wp eval-file scripts/dev/verify-sync.php      (15 checks)
→ wp eval-file scripts/dev/verify-accounts.php  (78 checks)
→ commit; deploy via wordpress/scripts/build-deploy-zips.sh + API flow
  in NEXT-SESSION.md; re-run staging Site setup; verify staging
```

Local-dev quirk: the `php -S` server holds a SQLite connection — if the
frontend ignores fresh DB writes, restart the server, it is not an
Elementor cache.
